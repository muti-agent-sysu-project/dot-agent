# 端到端评测报告（2026-11-05）

## 背景

用户在线提问"写 C 语言身份证校验代码 + 用我的号码验证"返回
`model_incomplete_answer`（36.82s）。排查发现三层问题并全部修复：

1. **截断即作废**：GLM-5.3-flash 思考 token 计入 completion 预算，
   2048 预算被 reasoning 吃掉后 `finish_reason=length` 直接抛异常，
   整次请求作废。→ 修复：预算翻倍重试一次（上限 8192），
   仍截断返回部分答案不报错（`pipeline._cloud_generate`）。
2. **云端网关超时 120s 过短**：长答案 reasoning+生成可超 120s，
   报 `model_connection_error`。→ 修复：云端默认 600s，
   `DOT_CLOUD_TIMEOUT_S` 可覆盖。
3. **预热失败崩溃循环**：旧代码 warmup `max_tokens=32` 不够思考模型，
   且预热失败直接 kill 服务 → systemd 崩溃循环。
   → 修复：预热 256 + 失败仅告警降级，服务绝不因预热退出。
4. **云端预算**：`DOT_BUDGET_CLOUD_ANSWER` 2048 → 4096。

## 测试集

`datasets/eval_cases.json` 18 条：本地直答×3、中难度×3、云端代码×2、
云端规划×2、隐私敏感×5、边界×3。跑法：

```bash
cd ~/dot-agent && source run.env
python3 scripts/eval_suite.py --base http://127.0.0.1:8766 --pause 1
```

## 结论与权衡

- **鲁棒性**：截断重试 + 预热降级 + 超时放宽后，原失败用例 52.6s 正常返回。
- **云端作用展示**：θ 是唯一开关。默认 θ 下 Qwen3-4B 一致率高，云端几乎
  不参与、隐私路径无法演示；标定 θ 后规划/代码类云端参与明显，
  CLOUD_MASKED/JUDGE 可复现。代价是时延上升（P95 118s→259s）——
  这是"省钱省时"与"能力/演示价值"的直接权衡，答辩时可作参数敏感性分析。
- **隐私**：两种 θ 下泄露均为 0；敏感实体从未出现在云端视图
  （部分用例分解器剥离数字后走 CLOUD_PLAIN 属正确行为）。
- **已知边界**：NER 规则后端对人名（张伟/李明）识别有限，人名依赖
  transformers 后端才能保证 HIGH 敏感度。
